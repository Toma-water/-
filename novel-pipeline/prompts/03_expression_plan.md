# プロンプト③ 表現設計(シーンごとに送る)

②で確定したJSONを貼って送る。

---

あなたは小説の技法設計の専門家です。
確定済みの内面分析(以下のJSON)をもとに、このシーンを「どう書くか」を設計してください。

## 入力

### 内面分析(確定済み)
(②で確定したJSONを貼る)

### 出来事
(events/scenes.md から該当シーンを貼る)

## 出力形式

次のJSON形式だけで出力してください。

```json
{
  "scene": 0,
  "pov": "視点(三人称一元・隊長 など)",
  "tone": "文体のトーン(例: 張りつめた静けさ / 乾いた淡々さ)",
  "show_vs_tell": [
    {
      "target": "伝えたい感情・情報",
      "method": "show(行動・情景・セリフに託す) or tell(地の文で直接書く)",
      "direction": "具体的な表現方針(例: 少女の淡白さは、返答の短さと箸の止まらなさで見せる)"
    }
  ],
  "beats": [
    "シーンの流れをビート単位で5〜8個(例: 1.茶を出される日常 → 2.北からの妖気で空気が変わる → ...)"
  ],
  "dialogue_ratio": "会話と地の文のおおよその比率と理由",
  "sentence_rhythm": "文のリズム(短文で緊迫/長文で沈思 など、箇所ごとに)",
  "motifs": ["使うモチーフ・象徴(例: 剣の鞘、白い式神、部屋の温度、団子)"],
  "opening_line_idea": "書き出しの方向性の案",
  "closing_line_idea": "シーンの締めの方向性の案",
  "avoid": ["このシーンでやってはいけないこと(例: 少女の心情を地の文で説明しすぎる)"]
}
```

## 設計のルール

- what_to_convey が「説明」ではなく「体験」として伝わる手段を選ぶこと。
- 視点人物が知り得ない情報を地の文に書かない設計にすること。
- 内面分析にある body_language を、ビートのどこで使うか具体的に割り当てること。
